# API Integration Guide

## Overview

This is an API-only messaging service where human users chat with AI bots. There is no web UI — all interaction happens through REST endpoints and an optional WebSocket for real-time bot communication.

**Base URL:** `http://localhost:4000` (dev)

---

## Authentication

There are two types of authentication:

### User Authentication (email/password → session token)

Users register and log in with email/password. The server returns a Bearer token used for subsequent requests.

```
Authorization: Bearer <USER_TOKEN>
```

### Bot Authentication (generated token)

Bots authenticate with a token generated by a user via the API. The token is shown once at creation time.

```
Authorization: Bearer <BOT_TOKEN>
```

## User API

### Register

```
POST /api/register
Content-Type: application/json
```

```json
{
  "email": "user@example.com",
  "password": "securepassword123"
}
```

**Response (201):**

```json
{
  "user": {"id": 1, "email": "user@example.com"},
  "token": "USER_SESSION_TOKEN"
}
```

### Login

```
POST /api/login
Content-Type: application/json
```

```json
{
  "email": "user@example.com",
  "password": "securepassword123"
}
```

**Response (200):**

```json
{
  "user": {"id": 1, "email": "user@example.com"},
  "token": "USER_SESSION_TOKEN"
}
```

### List Bot Tokens

```
GET /api/bot-tokens
Authorization: Bearer <USER_TOKEN>
```

**Response:**

```json
{
  "bot_tokens": [
    {
      "id": 1,
      "name": "my-bot",
      "is_connected": false,
      "is_working": false,
      "last_connected_at": null,
      "inserted_at": "2026-05-11T18:00:00Z"
    }
  ]
}
```

### Create Bot Token

```
POST /api/bot-tokens
Authorization: Bearer <USER_TOKEN>
Content-Type: application/json
```

```json
{
  "name": "my-bot"
}
```

**Response (201):**

```json
{
  "id": 1,
  "name": "my-bot",
  "token": "BOT_TOKEN_SHOWN_ONCE"
}
```

```
DELETE /api/bot-tokens/:id
Authorization: Bearer <USER_TOKEN>
```

**Response (204):** No content

```

Authorization: Bearer <USER_TOKEN>
```


**Response (201):**


### Show Conversation (with messages)

```
GET /api/conversations/:id
Authorization: Bearer <USER_TOKEN>
```

**Response:**

```json
{
  "id": 1,
  "title": "New conversation",
  "bot_token_id": 1,
  "messages": [
    {
      "id": 1,
      "role": "user",
      "content_type": "text",
      "body": "Hello bot!",
      "metadata": {},
      "model": "gpt-4o",
      "inserted_at": "2026-05-11T18:30:00Z"
    }
  ]
}
```

### Send Message (as user)

```
POST /api/conversations/:conversation_id/messages
Authorization: Bearer <USER_TOKEN>
Content-Type: application/json
```

```json
{
  "body": "Hello bot!",
  "model": "gpt-4o"
}
```

`model` is optional. When set, the bot receives it in the message payload and should use that model for its response.

**Response (201):**

```json
{
  "id": 1,
  "body": "Hello bot!",
  "role": "user",
  "content_type": "text",
  "model": "gpt-4o",
  "inserted_at": "2026-05-11T18:30:00Z",
  "conversation_id": 1
}
```

### List Bot Models

Get the available LLM models and token costs for a specific bot.

```
GET /api/bot-tokens/:bot_token_id/models
Authorization: Bearer <USER_TOKEN>
```

**Response:**

```json
{
  "models": [
    {
      "id": 1,
      "name": "gpt-4o",
      "input_cost_per_token": "0.000005",
      "output_cost_per_token": "0.000015"
    }
  ]
}
```

### Request Bot Model Refresh

Ask a specific bot to update its available models. The bot receives a `refresh_models` event via WebSocket.

```
POST /api/bot-tokens/:bot_token_id/refresh-models
Authorization: Bearer <USER_TOKEN>
```

**Response:**

```json
{
  "status": "refresh_requested",
  "bot_token_id": 1
}
```

### Request All Bots Model Refresh

Ask all of the user's bots to update their available models.

```
POST /api/bot-tokens/refresh-models
Authorization: Bearer <USER_TOKEN>
```

**Response:**

```json
{
  "status": "refresh_requested_all"
}
```

### Get Bot WebSocket Channel

Retrieve the channel code for a specific bot. Use this as the channel topic when joining the WebSocket — it keeps your authentication token private.

```
GET /api/bot-tokens/:id/channel
Authorization: Bearer <USER_TOKEN>
```

**Response:**

```json
{
  "bot_token_id": 1,
  "channel_code": "CHANNEL_CODE"
}
```

## REST API

### Get WebSocket channel code

Returns the bot's channel code for joining the WebSocket channel. Authenticated with the bot bearer token — no token ID needed.

```
GET /api/bot/channel
Authorization: Bearer <BOT_TOKEN>
```

**Response:**

```json
{
  "channel_code": "CHANNEL_CODE"
}
```

### Get new user messages

```
GET /api/bot/messages
```

Returns all user messages sent to conversations owned by this bot. Use `since` to poll incrementally.

**Query params:**

| Param   | Type   | Description                                      |
|---------|--------|--------------------------------------------------|
| `since` | string | ISO 8601 datetime. Only return messages after this time. |

**Response:**

```json
{
  "messages": [
    {
      "id": 1,
      "conversation_id": 5,
      "content_type": "text",
      "body": "Hello bot!",
      "metadata": {},
      "model": "gpt-4o",
      "inserted_at": "2026-05-11T18:30:00Z"
    }
  ]
}
```

### Send a message

```
POST /api/bot/messages
Content-Type: application/json
```

**Body:**

```json
{
  "conversation_id": 5,
  "content_type": "text",
  "body": "Here is my response."
}
```

**Response (201):**

```json
{
  "id": 2,
  "conversation_id": 5,
  "content_type": "text",
  "body": "Here is my response.",
  "metadata": {},
  "inserted_at": "2026-05-11T18:31:00Z"
}
```

### Update working status

Tell the UI whether the bot is currently processing. The user sees a "thinking..." indicator when `is_working` is `true`.

```
PUT /api/bot/status
Content-Type: application/json
```

```json
{
  "is_working": true
}
```

**Response:**

```json
{
  "is_connected": true,
  "is_working": true
}
```

### Set available models

Replace the bot's advertised LLM models and token costs. This is a full replacement — all existing models are removed and replaced with the provided list.

```
PUT /api/bot/models
Authorization: Bearer <BOT_TOKEN>
Content-Type: application/json
```

```json
{
  "models": [
    {
      "name": "gpt-4o",
      "input_cost_per_token": "0.000005",
      "output_cost_per_token": "0.000015"
    },
    {
      "name": "gpt-4o-mini",
      "input_cost_per_token": "0.00000015",
      "output_cost_per_token": "0.0000006"
    }
  ]
}
```

**Response:**

```json
{
  "models": [
    {
      "id": 1,
      "name": "gpt-4o",
      "input_cost_per_token": "0.000005",
      "output_cost_per_token": "0.000015"
    },
    {
      "id": 2,
      "name": "gpt-4o-mini",
      "input_cost_per_token": "1.5E-7",
      "output_cost_per_token": "6E-7"
    }
  ]
}
```

## Content Types

The `content_type` field controls what the user sees. Each type has specific field requirements.

### `text`

Plain text message. `body` is required.

```json
{
  "conversation_id": 5,
  "content_type": "text",
  "body": "Hello, how can I help?"
}
```

### `image`

An image. `metadata.url` is required. `body` is an optional caption.

```json
{
  "conversation_id": 5,
  "content_type": "image",
  "body": "Here is the chart you asked for",
  "metadata": {
    "url": "https://example.com/chart.png"
  }
}
```

### `video`

A video. `metadata.url` is required. Optional `metadata.mime_type` (defaults to `video/mp4`). `body` is an optional caption.

```json
{
  "conversation_id": 5,
  "content_type": "video",
  "body": "Demo recording",
  "metadata": {
    "url": "https://example.com/demo.mp4",
    "mime_type": "video/mp4"
  }
}
```

### `file`

A downloadable file. `metadata.url` is required. Optional `metadata.filename`. `body` is an optional description.

```json
{
  "conversation_id": 5,
  "content_type": "file",
  "body": "Export complete",
  "metadata": {
    "url": "https://example.com/report.pdf",
    "filename": "report.pdf"
  }
}
```

### `actions`

Suggested follow-up actions rendered as clickable buttons. `metadata.actions` is required (array of objects with `label`). `body` is an optional prompt shown above the buttons. When the user clicks an action, it sends the label text back as a normal user text message.

```json
{
  "conversation_id": 5,
  "content_type": "actions",
  "body": "What would you like to do next?",
  "metadata": {
    "actions": [
      {"label": "Show more details"},
      {"label": "Start over"},
      {"label": "Export as PDF"}
    ]
  }
}
```

## WebSocket API (real-time)

Connect to the Phoenix socket for real-time bidirectional messaging. Messages from the user are pushed to the bot instantly instead of requiring polling.

### Connect

```
ws://<HOST>:4000/bot/websocket?token=<BOT_TOKEN>
```

The server marks the bot as connected on successful handshake.

### Join your channel

After connecting, join your bot's channel. Use the `channel_code` retrieved from `GET /api/bot-tokens/:id/channel`. This keeps your authentication token private and out of the channel topic.

Phoenix channel join message:

```json
{
  "topic": "bot:<CHANNEL_CODE>",
  "event": "phx_join",
  "payload": {},
  "ref": "1"
}
```

### Receive user messages

The server pushes `new_message` events when a user sends a message:

```json
{
  "topic": "bot:<CHANNEL_CODE>",
  "event": "new_message",
  "payload": {
    "conversation_id": 5,
    "message": {
      "id": 1,
      "role": "user",
      "content_type": "text",
      "body": "Hello bot!",
      "metadata": {},
      "model": "gpt-4o",
      "inserted_at": "2026-05-11T18:30:00Z"
    }
  }
}
```

### Send a message

Push a `send_message` event to reply:

```json
{
  "topic": "bot:<CHANNEL_CODE>",
  "event": "send_message",
  "payload": {
    "conversation_id": 5,
    "content_type": "text",
    "body": "Here is my answer."
  },
  "ref": "2"
}
```

Reply on success:

```json
{
  "event": "phx_reply",
  "payload": {"status": "ok", "response": {"id": 2}},
  "ref": "2"
}
```

### Update status

Push an `update_status` event:

```json
{
  "topic": "bot:<CHANNEL_CODE>",
  "event": "update_status",
  "payload": {"is_working": true},
  "ref": "3"
}
```

### Receive model refresh request

The server pushes a `refresh_models` event when a user requests the bot to update its available models. The bot should respond by calling `PUT /api/bot/models` with its current model list.

```json
{
  "topic": "bot:<CHANNEL_CODE>",
  "event": "refresh_models",
  "payload": {}
}
```

### Heartbeat

Phoenix requires a heartbeat every 30 seconds or the connection is dropped:

```json
{
  "topic": "phoenix",
  "event": "heartbeat",
  "payload": {},
  "ref": "hb"
}
```

## Typical Bot Loop (REST polling)

```
1. GET  /api/bot/messages?since=<last_seen_timestamp>
2. For each message:
   a. PUT  /api/bot/status  {"is_working": true}
   b. Process the message
   c. POST /api/bot/messages  {response}
   d. PUT  /api/bot/status  {"is_working": false}
3. Sleep, then go to 1
```

## Typical Bot Loop (WebSocket)

```
1. Connect to ws://.../bot/websocket?token=<BOT_TOKEN>
2. GET /api/bot/channel to retrieve channel_code
3. Join channel "bot:<CHANNEL_CODE>"
4. PUT /api/bot/models with available models
5. On "new_message" event:
   a. Push "update_status" {"is_working": true}
   b. Process the message
   c. Push "send_message" {response}
   d. Push "update_status" {"is_working": false}
6. On "refresh_models" event:
   a. PUT /api/bot/models with current models
7. Send heartbeat every 30s
```

## Error Responses

| Status | Meaning |
|--------|---------|
| 401    | Missing or invalid bot token |
| 403    | Conversation does not belong to this bot |
| 422    | Validation error (check `errors` object in response) |

Validation error shape:

```json
{
  "errors": {
    "body": ["is required for text messages"]
  }
}
```
